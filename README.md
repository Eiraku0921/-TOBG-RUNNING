# TOBG-RUNNING

社会人・ジュニア向けランニングクラブのためのコミュニティ運営支援Webアプリ。

🔗 **ライブデモ: [tobg-running.com](https://tobg-running.com)**

---

## このプロジェクトについて

TOBG-RUNNINGは、藤蔭高校OBが立ち上げた社会人ランニングクラブ「TOBG」のために、個人で開発・運用しているランニングコミュニティサイトです。会員が日々の練習日記を投稿してお互いに共有し、普段なかなか会えないメンバー同士の親近感と、練習に対するモチベーションを維持する場として機能しています。また、陸上クラブに所属するメンバーの管理や、大会へのエントリーといったクラブ運営の実務もこのサイト上で行っています。

開発のきっかけは、高校卒業後に競技を続ける人と辞めてしまう人の二極化に疑問を持ったことでした。「誰でも参加しやすい社会人クラブチーム」を自分たちで立ち上げたものの、メンバーがそれぞれ別々の場所に住んでいるため、普段一緒に練習することができません。そこで、メンバーのモチベーションを維持するために、日々の練習をみんなで共有できる、ランニングに特化したコミュニティサイトを立ち上げ、運営しています。

このサイトは、私の高校時代の外部コーチにも実際に利用していただいています。そのコーチは小中学生向けのクラブチームの運営や、高校での外部コーチ活動をほぼボランティアで続けている方で、「将来社会人になっても陸上を楽しんで続けてほしい」という思いで活動されています。私たちが行っている活動は、その方が目指す「社会人競技者を増やす」という目標に対して、大学生世代からの働きかけとして貢献しているとの評価をいただき、現在はそのクラブチームから運営費(サーバー代)を出していただいており、スムーズに運営を続けられています。

ただし、このサイト・クラブチームはあくまで「クラブの人数を増やすこと」自体を目的にしているわけではありません。競技を趣味として続けたい人が続けやすい環境を整えたい、という思いから、クラブチームの運営とコミュニティサイトの開発・運用を行っています。

現在も実際に稼働しているこのサイトを対象に、運営メンバー向けの管理者機能の新設や、既存機能のUI改善に個人開発として段階的に取り組んでいます。

> このリポジトリは、ポートフォリオ公開用に機密情報(DB接続情報など)を除いた安全な状態で再構成したものです。実際の運用コードは別途管理しています。

## 主な機能

### 会員向け
- **練習日記**: 距離・時間・ペースなどを選択式でほぼ手入力なしに記録。写真・動画の添付、タイムライン/カレンダー表示の切り替え、いいね・コメント機能
- **NEXT PR(自己ベスト管理)**: 陸上・筋トレの種目ごとに自己ベスト/シーズンベストを記録。「大会」として投稿した練習日記から自動反映され、シーズン目標・長期目標の進捗を自動計算して可視化
- **グループ機能**: 招待コード/リンクで仲間だけのグループを作成し、練習日記の公開範囲を「全体公開・自分のみ・グループ限定」から自由に組み合わせて選択可能
- **大会エントリー・歴代記録**: 大会情報の確認とエントリー、チーム歴代記録(TOP5)の閲覧
- **PWA対応**: ホーム画面への追加でアプリのように利用可能。プッシュ通知、90日間のログイン保持に対応

### 管理者向け
- 会員管理(年会費の支払い状況管理)
- 大会エントリー・歴代記録の管理(自動照合による歴代記録の自動更新)
- お知らせ配信(サイト内通知+メール通知)
- 権限管理(階層的な管理者権限の設計)
- 活動状況を可視化するダッシュボード

## 直面した課題と解決(投稿数の減少)

このサイトは「練習日記をみんなで共有すること」を一番の目的として作りました。しかし、ある時期から日記の投稿数がはっきりと減っていく現象が起きました。

原因を考えたところ、「共有すること」だけを目的にしてしまうと、承認欲求が満たされた(あるいは飽きた)時点で使われなくなってしまうのではないか、という考えに至りました。そこで、自分が学生時代、毎日欠かさずつけていた「練習ノート」を思い出し、目的を見直し、一番の目的を「マイページの自分の練習カレンダーに記録を残すこと」に据え直し、みんなとの共有は、その副次的な効果として自動的に行われる形に設計を変えました。

もう一つの原因は、投稿画面にテキストエリアを1つ置いているだけだったことです。会員は投稿のたびに「何を」「どんな順番で」書けばいいかを自分で考えなければならず、結果として日記をつけることが「面倒」「時間がかかる」ものだと錯覚させてしまっていました。そこで、距離・時間・ペースなどの主要な項目をプルダウンなどを用いた選択式にし、かつ入力する順番もあらかじめフォームの流れとして決めておくことで、会員が何も考えずに上から埋めていくだけで、手入力をほとんど省いた形で投稿が完了するように作り変えました。

また、この経験から「一度離れてしまった(投稿しなくなった)会員を呼び戻すことの難しさ」も実感しました。使いやすくなった新しい投稿画面を、直接会った際にその場で操作して見せることで、変化を体感してもらい、利用再開につなげるという地道な対応で解消しています。

## 設計・実装で工夫した点

- **練習日記を中心としたデータ連携設計**: 練習日記を1件投稿するだけで、歴代記録・NEXT PR(自己ベスト管理)・週間練習グラフなど、他の複数機能にそれぞれ自動で照合・反映される仕組みを設計。会員は日記をつけるだけで、関連する記録が自動的に更新される
- **PWA化によるプッシュ通知の実現**: ホーム画面に追加することで、自分の練習日記へのコメントや大会情報などをプッシュ通知で受け取れるように。ホーム画面への追加(アイコン化)の手順がわかりにくいという課題に対しては、やり方をわかりやすく紹介する専用ページを用意して対応
- **画面遷移を減らすUI設計**: モーダルやアコーディオン展開を積極的に活用し、グループ作成・参加、各種設定などをページ遷移なしでその場で完結できるようにすることで、操作の手軽さとサクサク感を重視した設計
